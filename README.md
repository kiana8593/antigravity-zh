# Antigravity 简体中文补丁

适用于 **Google Antigravity Windows 独立桌面端 2.24.0** 的社区汉化补丁。与 Google 无隶属关系，不适用于 Antigravity IDE 的 VSIX 扩展。

**当前版本：v0.1.0，首个公开版本。** 已登记 287 条独立界面原文及 4 项原生退出窗口文案；支持安装前校验、原始备份和恢复。主要界面已现场检查，22 项自动化测试通过。仍有部分低频提示、模型/项目选择器状态及第三方插件说明保留英文，不承诺全界面覆盖。

## 下载与使用条件

从 **[Releases 下载 Windows 汉化包](https://github.com/kiana8593/antigravity-zh/releases/latest)**，选择 `antigravity-zh-v0.1.0-windows.zip` 并完整解压。

- 系统：Windows。
- 应用：Antigravity **2.24.0 独立桌面端**。工具还会核对可执行文件和归档指纹，同版本但文件不同也会停止。
- 环境：推荐 **Node.js 24 LTS（24.15.0 或更新的 24.x）**；也支持 Node.js 22.22.2+ 的 22.x 或 26+。可从 [Node.js 官网](https://nodejs.org/)安装。
- 双击安装和恢复工具无需执行 `npm install`，无需下载第三方汉化服务。

请完整解压发布包，不要只下载某一个 `.cmd`，也不要将 ZIP 当作 VSIX 导入应用。发布包不含 Antigravity 本体，需要先自行安装官方应用。

## 首次安装

1. 等待 Antigravity 中的任务完成，**完全退出应用，包括托盘和后台进程**。工具不会强制关闭任务。
2. 打开解压后的工程文件夹，双击 **`检查状态.cmd`**。
3. 版本和指纹检查通过后，双击 **`安装汉化.cmd`**。
4. 看到 **“汉化补丁已安装。”** 后，按任意键关闭窗口，再从原有快捷方式启动 Antigravity。

安装入口会自动构建、校验、备份和替换，无需单独构建或手动复制 `app.asar`。重复安装同一补丁会提示无需重复安装。

| 入口 | 功能 | 是否修改应用 |
| --- | --- | --- |
| `检查状态.cmd` | 检查版本、指纹、汉化状态和备份 | 否 |
| `安装汉化.cmd` | 构建、备份并安装补丁 | 是 |
| `恢复原版.cmd` | 使用原始备份恢复应用归档 | 是 |
| `构建补丁.cmd` | 仅在工程 `dist` 中构建并校验补丁 | 否 |

## 恢复英文界面

1. 完全退出 Antigravity。
2. 在**当初安装补丁的同一份工程**中双击 **`恢复原版.cmd`**。
3. 看到 **“已恢复原始应用，校验一致。”** 后重新启动应用。

**请保留整个 `backups` 目录。** 其中的 `original.asar` 和 `state.json` 是本机恢复所需文件，未包含在公开仓库或 Release 中。重新下载工程不能找回它们。恢复不会清空对话、项目和账号配置；备份缺失、损坏或当前文件无法识别时会停止。

## 更新补丁与应用版本

如果 Antigravity 本身仍是受支持版本，退出应用后，将新版发布包中的工程文件更新到原工程目录，**保留 `backups`**，再运行 `安装汉化.cmd`。工具会从已校验的原始备份重建，不覆盖已有原始备份。

通过 Git 获取工程的用户可在工作目录干净时运行：

```powershell
git switch main
git pull --ff-only origin main
```

Antigravity 自身更新后，旧补丁可能不再兼容。本工具不关闭自动更新，也不会把旧备份覆盖到新版应用。遇版本或指纹不匹配时，请等待适配。

## 自定义安装位置

双击入口默认操作当前用户的 `%LOCALAPPDATA%\Programs\antigravity`。通常使用普通用户权限即可。

如果安装位置不同，在工程目录打开 PowerShell，为每次操作指定相同的 `--app`。路径应为包含 `Antigravity.exe` 的文件夹：

```powershell
node tools/cli.cjs status  --app "D:\Apps\Antigravity"
node tools/cli.cjs install --app "D:\Apps\Antigravity"
node tools/cli.cjs restore --app "D:\Apps\Antigravity"
```

默认位置可以省略 `--app`。自定义位置安装后，恢复时也必须指定同一位置；双击入口始终使用默认位置。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 找不到 `node` | 安装受支持的 Node.js，重新打开终端或工程文件夹再试。 |
| 提示退出应用 | 等待任务结束并退出所有窗口和后台进程，再重试。 |
| 版本或指纹不匹配 | 等待当前版本适配，不要修改兼容性文件来绕过检查。 |
| 当前归档存在未知修改 | 可能由应用更新或其他工具造成，先确认修改来源。 |
| 备份缺失或损坏 | 确认使用原工程及完整备份目录；无法找回时请用官方安装程序修复或重装应用。 |
| `operation.lock`、`.tmp`、`.agzh-next` 冲突 | 可能是另一操作尚未结束或上次中断，保留现场检查，不要盲目删除备份。 |
| 归档强制校验开启 | 停止使用此方案；工具不会修改可执行文件或关闭安全校验。 |
| `EPERM` / `EACCES` | 确认应用已退出，并检查工程和安装目录的写入权限。 |
| 部分文字仍为英文 | 完全重启后检查；v0.1.0 仅覆盖已登记界面。 |
| 启动或中文显示异常 | 退出应用并使用同一工程的 `恢复原版.cmd` 还原，再提交问题。 |

## 覆盖范围与数据边界

已覆盖固定导航、内置侧栏标题、顶部菜单、部分概览入口和设置、自定义页面、自动化列表与表单、搜索和主输入占位提示，以及原生退出确认。

对话正文、实际输入、代码、终端、项目/文件/对话名称和模型名称不做通用替换。汉化模块不新增网络连接，不上传聊天或账号信息。

原始应用归档、解包资源、备份、日志、截图和凭据均不在仓库或发布包内。请勿在公开 Issue 中上传这些文件；反馈前请遮盖邮箱、用户名、本机路径和对话内容。

## 开发、测试与回滚

```powershell
git clone https://github.com/kiana8593/antigravity-zh.git
cd antigravity-zh
npm ci --ignore-scripts
npm test
npm run privacy
npm run build
npm run package
```

`main` 保存公开发布版本，`dev` 用于开发；`v0.1.0` 标签固定首版源码。词典位于 `dictionary/zh-CN.json`，每组词条绑定明确的界面范围。

工程回滚使用 `git revert` 保留历史；源码回退后还需重新构建和安装。Git 回滚不能代替应用原始备份。首次公开前历史已脱敏，持有旧开发副本的用户应重新克隆，勿将旧历史推入公开仓库。

适配详情见 [词条说明](docs/COVERAGE.md)、[验证记录](docs/VALIDATION.md)和[更新日志](CHANGELOG.md)。
