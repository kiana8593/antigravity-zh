# Antigravity 简体中文补丁

适用于 **Google Antigravity Windows 独立桌面端 2.24.0** 的社区汉化补丁，与官方无隶属关系。安装后仍从原来的 Antigravity 快捷方式启动，无需专用启动器。

> **当前为 `0.1.0-dev.1` 开发预览版。** 补丁已在本机完成备份及安装，15 项自动化测试通过；真实界面的中文显示、布局、多窗口和实际还原仍待验证，尚未发布正式版 `v0.1.0`。开发代码和使用工具位于 **[dev 分支](https://github.com/kiana8593/antigravity-zh/tree/dev)**；`main` 暂时仅保存初始化文档及本使用说明。

## 在这台电脑上使用

工程已经放在 **`AntigravityZh`**，补丁已经安装，无需再次下载工程或重复安装。可以直接打开 Antigravity 查看效果。

以下说明适用于首次安装、更新汉化词条和恢复英文界面。请保留工程中的 **`backups` 整个目录**，它是本机恢复原版所需的备份，不会上传到 GitHub。

## 使用条件与获取工程

- Windows，并已安装受支持的 Antigravity **2.24.0 独立桌面端**。本工具不是 IDE 的 VSIX 扩展，也不支持其他版本直接套用。
- 安装 **Node.js 22 或更新版本**，并确保命令行能运行 `node`。本机已经具备运行环境。
- 补丁安装、构建和恢复工具本身无需运行 `npm install`；额外依赖只用于开发测试。
- 工具会校验可执行文件与应用归档的指纹，即使显示版本相同，文件不匹配也会停止。

如需在新目录获取工程，在 GitHub 切换到 **dev** 分支，选择 **Code → Download ZIP** 并完整解压；也可以在已配置 GitHub 访问权限的终端中执行：

```powershell
git clone --branch dev https://github.com/kiana8593/antigravity-zh.git AntigravityZh
cd AntigravityZh
```

仓库为私有仓库，下载或克隆需要有访问权限。不要只下载某一个 `.cmd` 文件，也不要把 ZIP 当作 VSIX 导入应用。

## 首次安装：双击使用

1. **等待 Antigravity 中的任务结束，然后完全退出应用。** 如果应用仍在后台或系统托盘中运行，也需要退出。工具不会强制结束任务。
2. 打开完整解压的工程文件夹；本机位置为 `AntigravityZh`。
3. 双击 **`检查状态.cmd`**。正常情况下会显示版本 `2.24.0`，状态为“原版”或“已安装汉化补丁”。看到错误时先按下方“常见问题”处理。
4. 双击 **`安装汉化.cmd`**。工具会自动构建补丁、备份原始归档并安装，无需先双击构建入口，也无需手动复制 `app.asar`。
5. 窗口显示 **“汉化补丁已安装。”** 后，按任意键关闭该窗口，再通过原来的快捷方式启动 Antigravity。

安装相同补丁时会提示“已安装相同补丁，无需重复安装”。汉化主要覆盖固定导航、顶部菜单、概览入口和部分设置；仍看到部分英文属于当前开发版的覆盖限制。

| 文件 | 用途 | 是否修改应用 |
| --- | --- | --- |
| `检查状态.cmd` | 检查版本、文件指纹、汉化状态及备份 | 否 |
| `安装汉化.cmd` | 自动构建、备份并安装汉化 | 是 |
| `恢复原版.cmd` | 使用本机备份还原原始应用归档 | 是 |
| `构建补丁.cmd` | 仅在工程 `dist` 中生成并校验补丁，供开发检查 | 否 |

## 恢复英文界面

1. 等待任务结束，完全退出 Antigravity。
2. 在**当初安装补丁的同一个工程目录**中，双击 **`恢复原版.cmd`**。
3. 看到 **“已恢复原始应用，校验一致。”** 后，重新启动 Antigravity。

恢复仅还原补丁修改的应用归档，不会清空对话、项目或账号配置。若已经是原版，会提示无需恢复。**只从 GitHub 重新下载工程无法获得原始备份**；丢失或损坏备份时，工具会停止，不能把它当作可恢复状态。

## 更新汉化补丁

以下更新步骤适用于 **Antigravity 本身仍为受支持版本，且当前归档被工具识别** 的情况：

1. 等待任务结束并完全退出 Antigravity。
2. 在原工程目录中更新 `dev` 分支，保留本机 `backups` 目录：

   ```powershell
   git switch dev
   git pull --ff-only origin dev
   ```

3. 双击 **`安装汉化.cmd`**。工具会从已校验的原始备份重新构建并更新补丁，不会覆盖原始备份。
4. 显示安装成功后重新打开应用。

如果使用 ZIP 更新，请将新的工程源码合并到原工程目录，并保留 `backups`，不要删除整个旧工程后重新解压。若有自己修改的源码或词典，先保存这些修改，再更新。

**Antigravity 自身升级后，旧补丁可能失效。** 本工具不关闭自动更新，也不会把旧备份覆盖到新版应用。遇到版本或指纹不匹配时，请停止安装或恢复，等待新版本适配。

## 自定义安装位置与命令行用法

双击入口默认操作当前 Windows 用户的：

```text
%LOCALAPPDATA%\Programs\antigravity
```

例如本机是 `%USERPROFILE%\AppData\Local\Programs\antigravity`。通常使用普通用户权限运行即可；不需要因为使用补丁而默认以管理员身份运行。

如果应用安装在其他位置，请在工程文件夹中打开 PowerShell，向每个命令传入相同的 `--app` 路径。该路径应是包含 `Antigravity.exe` 的文件夹，**不是可执行文件本身**：

```powershell
node tools/cli.cjs status  --app "D:\Apps\Antigravity"
node tools/cli.cjs install --app "D:\Apps\Antigravity"
node tools/cli.cjs restore --app "D:\Apps\Antigravity"
```

默认位置可省略 `--app`。仅构建而不安装时运行 `node tools/cli.cjs build`。自定义位置安装后，恢复时也必须指定同一位置；双击入口仍只使用默认位置。

## 常见问题

| 看到的提示或现象 | 处理方式 |
| --- | --- |
| 提示安装 Node.js，或找不到 `node` | 安装 Node.js 22 或更新版本，重新打开终端或工程文件夹后再试。 |
| 提示先退出所有 Antigravity 窗口和后台进程 | 等待任务完成后退出应用，包括后台进程，再重新执行；不要在任务运行时强制结束。 |
| 版本或可执行文件指纹不匹配 | 当前应用不在已验证的适配范围内，等待适配，不要修改兼容性文件来跳过检查。 |
| “当前归档存在未知修改” | 应用可能更新或被其他工具修改，先确认修改来源；不要手动覆盖归档或删除检查记录。 |
| “原始备份缺失或损坏” | 确认正在使用原安装工程及完整 `backups` 目录；备份无法找回时需通过官方安装程序修复或重装应用。 |
| `operation.lock`、`.tmp`、`.agzh-next` 冲突 | 可能有另一个操作或上次操作中断。保留现场，确认无其他操作后检查，勿盲目删除备份或覆盖应用。 |
| 提示归档强制校验已开启 | 停止使用此补丁方案；工具不会关闭应用的安全校验。 |
| 提示权限不足、`EPERM` 或 `EACCES` | 先确认应用已完全退出，再检查是否对工程和安装目录有写入权限。 |
| 安装成功但仍有英文 | 完全退出并重新启动后检查固定导航和菜单；开发版仅汉化部分界面，真实显示效果仍待验证。 |
| 启动异常或中文显示不正常 | 退出应用，使用同一工程中的 `恢复原版.cmd` 还原后再反馈问题。 |

## 翻译范围与备份位置

- 已编写词条：固定导航、顶部常用菜单、概览的审阅/文件/终端/插件入口，以及部分设置标签、选项与说明。
- 不做通用替换：对话正文、用户输入、代码、终端、文件名、路径、项目名、对话标题、模型名称、第三方网页和操作系统对话框。
- 原始备份：工程内 `backups/<原始归档指纹>/original.asar`；同目录 `state.json` 记录安装位置与历次补丁指纹。请保留两者。
- `dist` 为本机构建输出；原应用资源、备份、日志和凭据均不上传 GitHub。

## 开发、测试与工程回滚

```powershell

npm run build
```

词典为 `dictionary/zh-CN.json`。每组词条绑定明确的界面范围，修改后需验证用户内容不会被误替换。
