# Antigravity 简体中文补丁

面向 **Google Antigravity Windows 独立桌面端 2.24.0** 的社区汉化工程，与官方无隶属关系。不是 IDE 的 VSIX 扩展。

## 当前状态

`0.1.0-dev.1` 开发预览。翻译原型、构建、安装及恢复工具已实现，自动化测试通过。**真实应用安装、中文布局、多窗口与完整恢复仍待现场验收，尚未发布 v0.1.0。**

工程：`AntigravityZh`。使用 Node.js 22 或更新版本。本地已提供 Node.js；使用安装和恢复工具无需下载额外依赖。

## 使用

1. 等待应用任务完成，然后完全退出 Antigravity（包括后台进程）。工具不会强制关闭应用。
2. 双击 `检查状态.cmd` 核对版本与状态。
3. 双击 `安装汉化.cmd`。成功后按原方式启动 Antigravity。
4. 需要恢复时退出应用，双击 `恢复原版.cmd`。

命令行等价入口：

```text
node tools/cli.cjs status
node tools/cli.cjs build
node tools/cli.cjs install
node tools/cli.cjs restore
```

默认安装目录为当前用户的 `%LOCALAPPDATA%\Programs\antigravity`。自定义位置通过 `--app "安装目录"` 指定，不支持自动识别多个安装。

## 已编写的翻译范围

- 固定导航：新建对话、对话历史、自动化、自定义、设置，以及部分导航提示。
- 顶部菜单：文件、视图、窗口及常用菜单项。
- 概览：审阅、文件、终端、插件等固定入口。
- 设置：固定设置导航，以及常规、应用和外观中的已登记标签、选项与说明。

上述项目仍需真实界面逐项验证。首版不承诺全覆盖。用户自定义分组标题、项目名、对话标题、模型名、低频错误、外部网页和系统对话框不做通用替换。对话正文、代码、终端、用户输入、文件名和路径不在翻译范围内。

## 备份与兼容性

- 安装校验应用版本、可执行文件和原始归档 SHA256；仅接受登记的原版或本工具记录的补丁版本。
- `backups/<原始归档指纹>/original.asar` 保存唯一原始备份，校验不通过即停止，绝不覆盖已存在的原始备份。
- `state.json` 记录安装路径与历次已安装补丁指纹；恢复和更新补丁依赖这些记录，请保留整个备份目录。
- 应用运行中、未知修改、版本升级、归档强制校验开启或写入冲突时停止。不修改可执行文件或安全开关，不关闭自动更新。
- 工具先生成新归档，逐文件校验并更新归档元数据，再使用同目录临时文件替换原归档。不会写入聊天、账号或智能体配置。
- 若操作被断电中断，先运行状态检查；若报告 `operation.lock` 或 `.tmp` 冲突，保留现场后检查，不要盲目删除备份或手动覆盖应用。

## 开发与测试

```text
npm ci --ignore-scripts
npm test
npm run build
```

词典位于 `dictionary/zh-CN.json`，每组词条绑定明确的界面选择器。增加词条时同时检查聊天、项目名和文件名的排除场景。源码不依赖 React 内部对象，不新增网络连接，翻译模块运行于现有隔离预加载环境。

构建输出与原始应用资源仅保存在本机，均被 Git 忽略。构建确定性依赖相同工程源码、词典和原版归档；历史工程回滚后须重新构建、安装才能改变应用。

## 版本管理与恢复

`main` 保存经过确认的阶段成果，`dev` 保存开发检查点。每项独立改动或一批词条完成后提交、推送并核对远程提交。只有通过现场验收才创建 `v0.1.0` 标签。

工程回退使用 `git revert <提交>`，随后运行测试、推送，保留既有历史。应用还原使用 `恢复原版.cmd`。Git 历史不能代替原始应用备份，备份未上传 GitHub。

完整过程和待验收项目见 [验证记录](docs/VALIDATION.md) 与 [实施计划](docs/PLAN.md)。
